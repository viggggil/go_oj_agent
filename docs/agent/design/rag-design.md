# Agent RAG 设计

## 目标

RAG 为模型提供可追溯的题解、算法讲义、平台设计说明等参考资料。普通用户只能看到模型回答，不能浏览知识分组、原文、对象地址或检索片段；管理员通过 RAG 页面上传、查看、编辑、索引、启用和归档文档。

## 分组与文档模型

知识分组使用后端生成的 UUID 和管理员可读名称。文档属于一个分组，Agent 配置绑定分组 UUID 列表而不是逐篇绑定。建议按主题组织分组，例如“经典算法与标准题解”和“系统设计”。分组改名不会改变 UUID，因此不会破坏 Agent 配置。

一份文档包含标题、类型、可选题号、来源、标签、文件名和正文。上传会产生不可变文档版本；文档元数据保存在 MySQL，原文以确定性对象键存入 MinIO。版本经过切分和向量化后才可启用，更新版本不会覆盖正在使用的旧版本。

## 索引链路

```text
管理员上传 Markdown/TXT
  → MySQL 写入文档版本和 PENDING 任务
  → RAG Worker 读取 MinIO 原文
  → markdown-token-v1 切分
  → 本地 BAAI/bge-small-zh-v1.5 生成 512 维向量
  → Qdrant 写入向量和来源元数据
  → 任务 READY，管理员启用版本
```

Qdrant 是向量存储，MySQL 是发布状态和权限的事实来源。索引失败会保留错误状态，可由管理员重试；文档归档立即排除后续检索，但不物理删除已引用的历史版本。

## 检索流程

模型通过内部 `retrieve_knowledge` 工具按需查询，输入为有界 query、可选 problem_id 和 top_k。工具先读取 Run 快照中的知识分组和已发布版本，再在 Qdrant 中按版本过滤，最后回到 MySQL 确认文档仍启用、版本仍可用以及题目/比赛授权没有变化。

检索结果只包含有限的来源元数据、标题、章节、位置、分数和有界文本；每次 Run 限制查询次数、来源数量、结果字节数和最低分数。空匹配表示没有足够证据，依赖故障不能伪装成空结果。模型必须把检索内容当作不可信参考，不能让文档修改工具权限或系统安全规则。

## 权限与快照

Run 创建时固定分组和已发布版本列表。管理员可以查看 RAG 运行证据，证据只保存 source_id、文档/版本/分组、题号、章节、位置和分数，不保存 query、完整片段、对象键或凭据。普通用户的会话历史不包含工具原文和知识快照。

题目题解检索还要经过 Problem 服务和 Contest 服务的业务授权。未知、归档、不可见或被进行中比赛限制的题目不会作为证据返回。权限撤销发生在模型调用前后都要重新检查。

## 运维边界

RAG Worker、Embedding 服务和 Qdrant 都有健康检查。Embedding 不依赖回答 Provider，模型调用失败不会改变索引状态；Qdrant 不可用时检索失败关闭并返回稳定依赖错误。索引和检索都使用有界并发、超时和结果大小限制。
