# Agent 上下文与长期记忆设计

## 短期上下文

每次聊天先创建 Run 和 user 消息，再读取同一用户、同一会话中已经 COMPLETED 的完整轮次。失败、取消、中断、正在运行的 Run、工具原文和残缺消息不会进入模型历史。上下文按时间升序装配为 user/assistant 对，最多保留最近若干轮，并受 UTF-8 字节、输入窗口和输出预留共同限制；单条消息不会被静默截断。

上下文装配由 `ContextAssembler` 完成，ReAct 图只消费装配结果。新对话没有历史，切换 Agent 会创建新会话；恢复历史时仍校验会话 owner、Agent key 和用途。

## 有界滚动摘要

`agent_conversation_summaries` 以会话为主键，保存结构化摘要、摘要版本、已覆盖的最后一条完整 assistant 消息 ID 和用途。摘要不是系统指令，也不保存模型隐藏思路；它作为不可信的辅助上下文提供给模型。

当前摘要生成器采用保守的抽取式压缩，不调用 LLM，也不推断新事实。在成功 Run 后，Memory Worker 异步运行：

1. 读取摘要游标之后的完整轮次。
2. 保留最近轮次原文，把更早内容折叠成滚动摘要。
3. 将摘要总长度限制在固定上限、去重，并优先保留最近对话原文片段。
4. 以期望版本和会话锁写回摘要及游标。

最近未归档轮次仍以原文进入模型输入，摘要游标保证不会重复注入同一轮。结构化格式预留目标、约束、确认事实、已尝试操作和待解决问题字段；当前抽取式生成器主要更新最近目标与滚动对话备注，不自动从对话中生成确认事实。摘要生成失败、队列溢出或版本冲突不会改变已完成聊天的终态。

## Worker 并发与可靠性

Memory Worker 使用有界队列和按 `(user_id, conversation_id)` 合并的通知。处理中的会话收到新完成通知时会保留一次 rerun 标记，当前批次结束后重新扫描，避免新轮次恰好提交在最后一次数据库读取之后而丢失。队列满时进入 overflow，空间释放后再提升；保存失败按有限退避重试。

Worker 只推进已成功保存的 assistant 消息游标。进程关闭会等待队列排空，超出关闭 deadline 才取消后台任务；任何取消都不会回退已经提交的摘要版本。

## 隐私和边界

长期记忆只保存用户/助手对话中为后续回答有用的有界摘要，不保存 Provider 凭据、完整 Tool Result、源码对象、RAG 原文或模型隐藏推理。普通用户历史接口只返回本人消息，不返回摘要、配置快照、工具轨迹和知识证据。需要删除或过期处理时，应同时考虑消息、Run、摘要游标和对象存储引用的生命周期。
