# Agent 上下文与长期记忆设计

## 短期上下文

每次聊天先创建 Run 和 user 消息，再读取同一用户、同一会话中已经 COMPLETED 的完整轮次。失败、取消、中断、正在运行的 Run、工具原文和残缺消息不会进入模型历史。摘要覆盖边界之后的轮次按 assistant 消息 ID 升序分页读取；没有摘要游标时，同样从最早轮次开始读取。

最近最多六轮以完整 user/assistant 对进入上下文，并受字符数、UTF-8 字节、模型输入窗口和输出预留共同限制。超过原文窗口的未覆盖历史由本地抽取生成临时衔接摘要，再与持久化摘要一起提供给模型；不会只取最近 24 轮而跳过中间历史。预算检查使用实际模型 Prompt、技能、工具目录和摘要，因预算放不下的完整轮次同样进入临时衔接摘要。临时摘要不调用 LLM、不写数据库、不推进持久化游标；其中的原文片段仍是不可信辅助上下文。分页和处理时间有上限，超过上限时显式失败，不伪装为完整历史。

上下文装配由 `ContextAssembler` 完成，ReAct 图只消费装配结果。新对话没有历史，切换 Agent 会创建新会话；恢复历史时仍校验会话 owner、Agent key 和用途。

## 有界滚动摘要

`agent_conversation_summaries` 以会话为主键，保存结构化摘要、摘要版本、已覆盖的最后一条完整 assistant 消息 ID 和用途。摘要不是系统指令，也不保存模型隐藏思路；它作为不可信的辅助上下文提供给模型。

真实模型模式下，Memory Worker 使用该会话已完成 Run 的不可变模型/Provider 配置和现有凭据读取链路，通过 LLM 生成结构化增量；不会复用聊天 Prompt、技能或工具权限。在成功 Run 后异步运行：

1. 从最早的未覆盖完整轮次开始，每批最多归档六轮，保留最近六轮原文。
2. 输入旧摘要和新增轮次，生成目标、用户约束、确认事实、已尝试操作、待解决问题、备注及明确失效的旧条目。超长消息按 UTF-8 安全边界分窗口处理所有原文，不在截掉整段消息后推进游标。
3. 严格解析 JSON，拒绝重复键、额外字段、类型错误和超限内容。每条新增/更新/删除都必须引用本次输入的消息 ID 和连续原文；程序检查消息存在、原文匹配及用户/助手角色。用户目标、约束和确认事实只能引用用户消息，不能把助手说法升级为已验证事实，也不能生成新的 `tool_fact`。
4. 独立发起一次 LLM 核验，检查增量是否被原文支持、是否丢失否定或不确定性、是否混淆计划与实际执行、是否错误删除旧条目或保存敏感内容。核验输出也必须符合严格 schema；拒绝或无法解析时不发布增量。
5. 由程序合并已验证增量，保留未明确失效的旧条目并去重。每类最多 32 条，总 JSON 最多 12,000 字节；超预算按整条淘汰旧内容，优先保留目标和用户约束。
6. 整批处理成功后，以期望版本和会话锁原子写回摘要及覆盖游标；任一窗口失败则保留旧摘要和旧游标，等待有限重试。

持久化摘要、临时衔接摘要和最近原文构成连续的覆盖区间，避免后台摘要落后时出现中间空洞。Fake/演示模式仍使用本地抽取式生成器。摘要生成失败、队列溢出或版本冲突不会改变已完成聊天的终态。原文依据校验与语义核验用于降低幻觉风险，摘要仍然可能过时或不完整，不能替代实时业务授权与本轮业务事实核对。

## Worker 并发与可靠性

Memory Worker 使用有界队列和按 `(user_id, conversation_id)` 合并的通知。处理中的会话收到新完成通知时会保留一次 rerun 标记，当前批次结束后重新扫描，避免新轮次恰好提交在最后一次数据库读取之后而丢失。队列满时进入 overflow，空间释放后再提升；保存失败按有限退避重试。

Worker 只推进已成功保存的 assistant 消息游标。进程关闭会等待队列排空，超出关闭 deadline 才取消后台任务；任何取消都不会回退已经提交的摘要版本。

## 隐私和边界

长期记忆只保存用户/助手对话中为后续回答有用的有界摘要，不保存 Provider 凭据、完整 Tool Result、源码对象、RAG 原文或模型隐藏推理。普通用户历史接口只返回本人消息，不返回摘要、配置快照、工具轨迹和知识证据。需要删除或过期处理时，应同时考虑消息、Run、摘要游标和对象存储引用的生命周期。
