### `multi_turn_learn_dp_knapsack`

改动前：完成 / 未通过 / 3.40；改动后：完成 / 通过 / 4.00。

旧回答统一重评：三个主问题基本完成：dp[j] 语义、正序导致同一物品重复使用的推演、0/1 与完全背包方向及次数语义均解释正确。但补充的循环嵌套部分存在实质技术错误：外层容量、内层物品时，0/1 背包物品倒序仍会重复使用物品；用 w=2,v=3,m=4 单物品可核验得 dp[4]=6。因此技术正确性受限，不能通过。

新回答评审：三轮回答均承接前文：首轮给出一维 dp[j] 语义及逆序提示；次轮以 w=2,v=3,V=4 推导正序得 6 并对比逆序正确结果；第三轮表格对比 0/1 与完全背包的遍历方向、读旧值/新值及物品使用次数语义，并补充二维对应和边界。内容技术正确，小样例可核对，未发现违规或缺失。

脚本核验：旧回答声称容量外层、物品倒序即可保证 0/1 语义。仅有重量 2、价值 3 的一件物品，容量 4 时，此写法仍得 6，正确是 3。原内置评审技术维度给 4，漏掉了补充表格的错误。

## 限制与后续优先级

- 每侧只有一次目标运行，不能证明统计显著改进，也不能排除 Provider、检索和模型抽样波动；未对 Prompt、Skill、预算和 Provider 修复分别做消融。
- 评分缺失不能假设为随机，配对质量只代表双方均可评分的子集。评审接收有界问答、rubric 和脱敏执行证据，长多轮输入可能截断。模型评分仍可能遗漏或误判，本次仅对部分可疑结论做最小反例验证，没有全部案例的独立人工评分。
- 执行完成不等于答案正确；继续减少不必要的长篇补充并验证反例。仍失败的目标应按预算或 Provider 错误定位，不用补评掩盖。
- 优先补齐评审输入中的业务工具结果摘要，再做人工抽检；只传工具名会让真实取得题库信息的回答缺少可见证据，不应以关键词匹配替代。
- 建议修订错配标题/证据并版本化数据集，然后做多次配对复测；新数据集结果不能覆盖本次固定数据集结果。
