# Agent RAG 实施计划（讨论稿）

当前真实聊天已具备 LangGraph、模型 Responses 调用、完整成功轮次历史、只读业务工具和 Agent/Skill 管理。
RAG 尚未实现，Agent 的 knowledge_scope 目前只允许为空。本计划首阶段以已发布、当前用户可见的题解为核心，同时支持算法讲义和平台文档，
后续再扩展私有笔记和检索质量。不把 Skill 与知识文档混为一类：Skill 描述任务方法，RAG 提供回答证据。

## 目标与验收

管理员上传 Markdown/TXT、查看索引状态并发布到知识库；Agent 绑定知识库后，聊天按需检索并引用
已发布文档。用户可以打开来源、文档版本和引用位置。无匹配证据时明确说明，继续基础回答或只读
业务查询。题号/提交的实时信息仍经所属 Go 服务 gRPC 获取，不依赖可能过期的向量文档。

已确认首版优先题解，同时支持算法讲义和平台文档；输入格式 UTF-8 Markdown/TXT，不先加入
OCR、PDF 复杂布局、网页爬取或用户私有笔记。先收录明确发布且公开题目可访问的题解；未发布、
比赛中及未确认可见条件的题解默认排除。按题号检索必须先经 Go 业务服务确认题目可见，
题解发布状态与读取权限由权威元数据校验。当前题目服务没有题解发布接口，需要明确由 Agent
管理员上传并发布自有知识题解，还是新增 Problem 所属题解领域；推荐首版使用前者，避免镜像业务数据。

## 当前路径与运行方式

用户 → Gateway 鉴权 → Agent 配置快照与本人历史 → LangGraph → Responses 模型 → 只读工具 → SSE。
Issue #169 将普通聊天的绑定 Skill 作为当前问题的任务参考，模型自行采用适用说明，不增加分类调用。
RAG 推荐作为 `retrieve_knowledge` 只读工具接入同一有界循环：模型按需检索，检索结果经程序过滤与
预算控制后回到模型。回答必须引用已有 source_id，最终校验拒绝编造来源编号。

不在每条“你好”上固定检索，不引入新的通用 Agent 框架，不启用节点自动重放或持久化恢复。
后续如检索召回不足，可基于评测增加查询改写或固定检索节点；它们的调用与成本仍计入整体预算。

## 建议技术选型

| 层 | 建议 | 决策及理由 |
| --- | --- | --- |
| 文档/版本/索引任务状态 | Agent 自有 MySQL | 作为真源，复用服务所有权与迁移机制 |
| 原始文档 | MinIO 独立知识文档 bucket | 复用已有设施，按内容哈希/版本使用不可变对象键 |
| 向量库 | Qdrant，开发与部署统一 | 支持元数据过滤；避免 Chroma 开发/Qdrant 部署的双实现。现架构文档写的是开发 Chroma，采用本建议需同步 ADR/文档 |
| 中文 embedding | 本地 BAAI/bge-small-zh-v1.5（建议） | 用户确认 su8 无 embedding，采用本地中文小模型；先用 CPU、512 维向量与该模型输入上限做基线，模型 revision 固定，后续按评测升级 |
| 文档解析/切分 | Markdown 标题优先，保留代码块与位置 | 可用小型库/自有逻辑，避免为初版引入整套编排框架。按所选 embedding tokenizer 计数，BGE-small-zh-v1.5 初始约 300–380 tokens、重叠约 40–60，含指令和特殊 token 不超过 512；长代码按结构拆分，需用实际题解评测调整 |
| 初版检索 | 向量召回 + 元数据筛选 | 先建立可量化基线，top-k/阈值/上下文预算可配置，不能跨 embedding 模型共用阈值 |
| 混合检索/重排 | 第二阶段按评测加入 | OJ 的算法名、题号、符号适合关键词补充；先保留接口，必要时增加稀疏检索与融合、cross-encoder 重排，避免首版额外重排服务 |
| 索引异步任务 | MySQL 任务表 + 租约 worker | 初版复用可靠持久化，不要求新 MQ 事件。worker 拉取任务/续租、超时重领，Agent 保持 API 响应速度；若改 MQ 通知必须同事务 Outbox |

Embedding 与 su8 回答模型分开部署。本地 embedding 建议作为独立轻量 HTTP 服务，CPU 加载
固定 revision 模型，批处理有界；查询端/索引 worker 共享模型版本、归一化和 query 指令规则。
提前下载并固定模型，正常运行不依赖外网。验证宿主 CPU、内存、文档规模和查询并发后设限。
模型更换或维度更换必须建立新索引并切换，禁止向同一集合混入不兼容向量。

## 数据和安全不变量

- Agent 只直接访问 oj_agent 与自己管理的 MinIO 对象/Qdrant 索引；不读其他服务业务数据库。
- 规划知识库、文档、不可变文档版本、索引 generation、索引任务、chunk 元数据。上传者、
  发布状态、版本、内容哈希、embedding/splitter 版本、对象键、source_id/标题/章节均可追踪。
- Agent 的 knowledge_scope 引用知识库标识；Run 固定已发布索引 generation。归档/权限撤销
  每次检索和来源访问都检查最新状态，覆盖旧快照，保证不能继续泄露已撤销内容。
- 所有检索只使用当前 Agent 配置与可信用户身份的范围。Qdrant 查询前加知识库/generation/可见性
  筛选，返回后再验证权威元数据；无匹配范围时不可回退到全库。引用来源访问同样鉴权。
- 文档视为不可信材料，不能改变系统规则或工具权限；结果只提供短证据和受控来源元数据。
  不把凭据、推理过程、整份文档或私有正文写入普通运行日志。
- 来源编号与元数据由程序产生，最终回答只允许引用本轮实际返回的来源。普通用户不接触原始对象键。
- 题解可见性、比赛隔离、私有 owner 隔离属于真实授权，不能只写在 Prompt 内。首版题解限明确发布、公开可见的范围；默认拒绝比赛中和未发布题解，私有笔记后续独立实现。

## 摄取、发布与失败收敛

上传限制类型/编码/大小；写入不可变对象后，在 MySQL 事务中登记文档版本与待处理任务。
对象写成功但 DB 失败会留下孤立对象，使用暂存标记/受控清理任务回收；不在失败时删除已引用版本。
上传请求提供 request_id/内容哈希，重复上传/重试按明确幂等规则返回同一操作结果。

任务按文档版本 + splitter_version + embedding_model + generation 唯一。worker 使用租约、有限
批大小、批次进度与有界重试；向量 point ID 由 generation/chunk 编号确定，重复 upsert 幂等。
embedding 限流/断线时记录脱敏失败、退避重试，超过次数进入 FAILED，管理员可明确重试。

新索引完全就绪、校验 chunk 数/向量维度后才能发布；在 MySQL 事务中原子切换 active_generation。
半成品不参与检索。新版本准备失败保留旧发布版本。旧 generation 按引用/保留策略清理，不能
切换后立刻删除正在运行会话所需的旧版本。撤销可见性即时优先于保留引用。

Qdrant/embedding 不可用时返回明确的检索失败结果，不声称检索成功；RAG 工具消耗已有工具次数、
时间和结果字节预算，查询向量化另外限制 embedding 调用次数/批量与成本。

## 分阶段 PR

1. **PR1：题解与公开文档摄取和检索内核。** 按本地小模型/Qdrant 方案增加独立适配器、Compose
   Qdrant、MySQL 迁移、MinIO 管理、文档版本与租约索引任务、CLI 导入/发布/检索。先用少量
   Markdown 题解与讲义验证“上传→索引→检索”，不做空页面。每次 PR 留下可运行的闭环。
2. **PR2：接入 LangGraph 回答与引用。** 开放受控 knowledge_scope，`retrieve_knowledge`
   进入现有工具目录/执行循环，固定索引版本、检索预算、来源校验。Gateway/SSE 增加版本化或
   向后兼容的 citation 契约，聊天显示可点击引用，来源内容入口同身份校验。
3. **PR3：前端知识库管理。** 文档上传、任务状态/失败重试、切分预览、检索测试、发布/归档，
   Agent 页面绑定知识库。不可检索/发布时明确提示，不让管理员手填内部对象键或向量 ID。
4. **PR4：质量优化与扩展语料。** 小型中文 OJ 数据集衡量召回、引用正确率、证据不足处理、
   延迟/成本；据结果增加关键词融合、重排、查询改写。题解在首版即验证题目/发布可见性，私有笔记后续独立接入。

## 验证矩阵和文档影响

少量有意义的单元测试覆盖切分/引用验证；实际 MySQL/MinIO/Qdrant 集成验证版本发布、租约
重领、重复索引、embedding 失败、归档过滤与索引版本切换；Gateway/浏览器验证上传、发布、
聊天引用来源及越权拒绝。一个小语料评测集包含有证据、无证据、注入文本、版本变化、符号/算法名。

修改 docs/api.md、database.md、architecture.md 与 Agent README；选型确定后新增 ADR。
新增功能走 Issue→PR→CI→独立审查；纯界面小调整/小修复复用必要检查，省略独立审查。

## 已确认与剩余决策

已确认：首批语料以题解为核心，兼容算法讲义/平台文档；su8 无 embedding，使用本地中文小模型。

建议默认采用 Qdrant + BAAI/bge-small-zh-v1.5 CPU，固定模型 revision 与 512 维向量；开发和部署
统一 Qdrant，替代原文档中的 Chroma→Qdrant 双路线，落地时写 ADR。

仍需产品决策：首版题解采用管理员上传/发布的 Agent 知识文档，还是建设 Problem 服务自有的题解
发布领域。推荐先做管理员上传，要求关联 problem_id，并在读取时经 Go 服务确认题目可见。
后续自动同步官方题解时通过 gRPC/事件接入，Agent 不直接访问业务数据库。

教学行为建议默认“提示优先”：用户只要思路时返回分级提示，明确要求完整解法时再返回完整题解；
这只是回答策略，不能代替比赛/发布可见性的硬授权。如果希望默认直接给完整解法，可调整 Skill。

切分大小、top-k、相似度阈值与何时重排属于可评测的实现参数，先设有界默认值，不要求用户逐项拍板。
